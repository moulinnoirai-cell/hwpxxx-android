# Android 0.3.0 — PC 1.6.1 편집 기능과 태블릿 가로 화면

기준: `moulinnoirai-cell/hwpxxx` main / PC 1.6.1, Android 0.2.0.

- 기울임, 자간(-50~50%), 장평(50~200%), 문단 위·아래 간격(1/200pt 단위)을 추가했습니다.
- 글자 모양 / 문단 모양 / 둘 다 / 문단 스타일을 복사하고 한 번 적용하는 모양 복사를 추가했습니다. 표 안에서는 셀 속성 및 테두리·배경도 복사할 수 있습니다(터치로 선택한 한 칸에 적용).
- HWP/HWPX 메모 목록, 삽입, 수정, 삭제, 본문 위치 이동, 초록색 앵커 표시와 되돌리기/다시 실행을 추가했습니다. 충분히 넓은 화면(1600 CSS px 이상)에는 여백 메모 상자와 안내선을 표시합니다. 좁은 화면은 메모 패널을 이용합니다.
- 형광펜 모드에서는 글자를 선택할 때마다 현재 색을 적용합니다. 색 없음은 기존 Android와 같은 흰색 음영입니다. Esc 또는 형광펜 단추로 모드를 해제합니다.
- 표 칸 합치기에서 선택 범위를 병합 칸 전체로 확장합니다. 시작·끝 칸을 고르는 터치 UI를 사용합니다. 겹친 표의 칸 합치기는 지원하지 않습니다.
- 기존 Android의 표 안 텍스트 붙여넣기 경로를 유지합니다. Windows 한/글 전용 HTML 클립보드 경로는 이식하지 않았습니다(Android에서 같은 형식의 클립보드를 만들 수도, 검증할 수도 없습니다). PC판도 엔진 수정이 필요해 넣지 않은 '여러 칸에 나눠 붙이기'는 앱 수준에서 다음과 같이 따로 제공합니다: 표 패널의 '칸별 붙여넣기'에 탭(열)·줄 바꿈(행)으로 나눈 글을 붙여 넣으면 선택한 칸부터 한 칸씩 채웁니다. 표 밖으로 나가거나, 병합 칸이 있거나, 목적 칸에 문단이 여러 개이면 아무것도 바꾸지 않고 거절하며, 한 번의 실행 취소로 되돌립니다.
- 여러 문단 선택: 마우스 드래그(작은 창·DeX), Shift+클릭, Ctrl+A(두 번째 누름)로 본문 한 구역 또는 표 한 칸 안의 여러 문단을 선택합니다. 선택한 범위에 글자 서식·문단 서식·형광펜을 한 번에 적용하고, Backspace/Delete/입력/Enter/붙여넣기로 한 번의 실행 취소 단위로 바꾸거나 지웁니다. 범위에 표·그림이 들어 있으면 지우기·바꾸기를 거절합니다(복사와 서식은 허용). 표 경계나 구역 경계를 넘는 선택은 지원하지 않습니다(엔진의 삭제·복사 API가 한 본문 구역 또는 한 칸 안에서만 동작).
- 같은 문서 안에서 복사한 글은 엔진 클립보드로 붙여 서식을 유지합니다. 다른 앱에서 복사한 글이나 엔진 복사에 실패하면 이전처럼 일반 글자로 붙입니다.
- 문서함의 PDF 저장이 암호 문서도 지원합니다. 저장 폴더를 고른 뒤 암호를 묻고(암호는 문서 엔진 메모리에서만 사용), 저장되는 PDF에는 암호가 걸리지 않는다는 점을 먼저 알립니다. 틀린 암호는 아무 파일도 만들지 않습니다.
- 강제 종료 복구: 저장하지 않은 편집은 입력을 잠시 쉬면(보통 약 4초, 문서 용량이 크면 더 길게, 최대 30초. 약 10MB에서 30초), 앱이 백그라운드로 갈 때는 즉시, 쉬지 않고 계속 입력하는 중에는 마지막 복구본에 들어가지 않은 첫 편집으로부터 **최대 30초 안에** 앱 내부 저장소의 비공개 복구본으로 보관합니다(한글 조합 중이거나 편집 반영·다른 작업이 진행 중이면 0.5초 간격으로 다시 시도하며, 최대 대기 시간은 계속 흐릅니다. 저장이 진행되는 동안에는 복구본을 쓰지 않고 같은 방식으로 다시 시도하므로, 저장이 실패하면(다른 앱의 수정, 읽기 전용, 공간 부족, 시간 초과) 새 입력 없이도 곧 복구본이 만들어집니다). 다음 실행 때 '저장하지 못한 편집 내용이 있어요'로 알리고, 복구한 내용은 원본을 바꾸지 않고 새 파일로만 저장합니다. 저장·편집 취소로 폐기하면 복구본도 지웁니다. 복구본은 **마지막으로 성공한 시점의 스냅숏**입니다. 그 뒤에 입력한 내용(계속 입력 중이면 최대 약 30초 분량)은 복구되지 않으며, 첫 복구본이 만들어지기 전의 종료는 복구할 수 없습니다. 어떤 종료에서도 복구된다는 보장은 아닙니다. 암호 문서의 복구본도 암호가 유지됩니다.
- 하드웨어 키보드의 Ctrl+S/B/I/U/Z/Y, Alt+C를 KeyboardEvent.code로 처리해 한글 입력 상태에도 같은 물리 키가 동작합니다.
- 저장 내보내기 당시 리비전을 기억하고 저장 완료 시 비교합니다. 디스크 기록 중 추가 편집이 있으면 수정 상태가 유지됩니다. 저장 중에는 편집 취소·문서 닫기를 막고, 읽기 전용 문서는 덮어쓰지 않으며, 다른 앱이 문서를 바꿨으면 원본과 백업을 그대로 두고 '다른 이름으로 저장'을 바로 제안합니다. 비정상 종료가 남긴 임시 파일(`.hwp-offline-*.tmp`, 6시간 이상)은 다음 저장 때 정리합니다.
- 갤럭시 탭 S7 가로 화면(기본 배율 기준 1280×800 CSS px)을 포함해 1000px 이상의 가로 창에서는 도구·서식·메모 패널을 오른쪽으로 옮깁니다. 화면 회전·키보드 크기 변화 때 WebView나 입력 요소를 다시 만들지 않습니다. 자동 회전을 따르고 멀티 윈도우 크기에 맞춥니다.
- DeX의 물리 키보드·마우스 조작을 추가했습니다. Ctrl+휠은 포인터를 기준으로 문서만 확대하며 본문 클릭은 배율을 바꾸지 않습니다. Ctrl+0/+/-, Ctrl+Shift+S, 문단 간 이동, 문단 끝 Delete, PageUp/Down을 지원합니다.
- 설정에서 Termux의 프로젝트 폴더를 연결해 하위 폴더의 HWP/HWPX를 검색하고 엽니다. 폴더 읽기 권한은 재시작 후에도 유지됩니다. 편집 결과는 기기 저장소에 복사본으로 저장하며 Termux 원본을 직접 변경하지 않습니다. 제공자 호출은 제한 시간(폴더 목록 20초, 연결 확인 6초, 문서 읽기 45초)과 취소를 갖고, 응답 없는 제공자는 3개 폴더 연속 시간 초과 후 건너뜁니다. 깊이·개수 한도에 걸려도 해당 폴더의 문서는 계속 나열합니다. 연결 확인이 실패하면 허용 권한을 남기지 않습니다.
- 인터넷 권한, 외부 전송, 원격 리소스는 추가하지 않습니다.

## 엔진과 빌드

PC판의 PR #8269 백포트 패치를 동일하게 포함했습니다. Android 11의 구형 WebView에서도 실행되도록 Rust nightly-2026-02-01과 rust-src로 표준 라이브러리까지 WebAssembly MVP 대상으로 다시 빌드합니다. `config/android-engine.json`에 원본 커밋·패치 체크섬·도구 버전을 기록합니다. `bash scripts/build-engine.sh <별도 rhwp 체크아웃>`으로 엔진을 만든 후 Gradle로 빌드합니다. 예전 엔진을 실수로 넣은 APK는 `verifyMemoEngine` 작업에서 빌드를 막습니다.

GitHub Actions `Android tablet build`는 엔진 빌드, 문서 왕복 시험, FileStore 시험, 4개 화면 크기의 브라우저 시험, lint, debug/release APK 생성을 수행하도록 구성했습니다. debug APK는 `kr.offline.hwp.preview` / `hwpxxx 미리보기`로 별도 설치할 수 있습니다. 정식 release APK로 기존 앱을 업데이트하려면 원래 release 서명이 필요합니다. 기존 앱 데이터나 문서를 삭제하지 마세요.

포장되는 엔진은 Gradle `verifyMemoEngine`이 매 빌드 전에 확인합니다. 생성된 `build-info.json`이 필요하고, 고정 값(`config/android-engine.json`)과 `rhwp.js`·`rhwp_bg.wasm`·`rhwp.d.ts`의 실제 SHA-256이 일치해야 합니다(`scripts/verify-engine.mjs`, 끄는 방법 없음). `build-info.json`과 `rhwp*` 빌드 결과는 파이프라인이 생성하며 소스 변경으로 커밋하지 않습니다. 엔진 빌드 안내는 `patches/rhwp-engine/README.md`에 Android용으로 바로잡았고, 리뷰에서 발견한 저장소 안의 미사용 10 MB 임시 파일(`app/src/main/assets/engine/.rhwp_bg.wasm.my6jCi`, 첫 가져오기부터 추적됨, 점 파일이라 APK에는 들어가지 않음)은 제거하고 같은 패턴을 `.gitignore`에 추가했습니다(Git 기록은 다시 쓰지 않았습니다). Termux QA APK는 저장소에 고정한 SHA-256(`scripts/fetch-termux-qa.sh`)으로 검증합니다.

## 확인 범위

이전 Actions 실행(커밋 5986d59)에서 엔진/편집 회귀 시험 11건, FileStore 48건, 브라우저 화면 크기 4종, lint와 debug/release APK 빌드를 확인했습니다. 설치 APK의 최종 검증 대상은 사용자 요청에 따라 갤럭시탭 S7의 Android 13(API 33)입니다. 해당 최종 커밋의 실행 상태와 APK·화면·로그 링크는 PR #2에 기록합니다. 실제 Tab S7/DeX/삼성 키보드/Bluetooth 연결 및 한컴 프로그램에서의 재열기 시험은 아직 수행하지 않았습니다.

Windows Electron 앱 및 PC MCP 등록·외부 AI 연결은 Android 앱의 범위가 아닙니다. Android는 계속 오프라인 앱으로 동작합니다.

## 코드 리뷰 반영

`docs/CLAUDE-REVIEW.md`에 최초 Opus·high 리뷰 원문과 항목별 처리(F1~F18, H1~H7)를 기록했습니다. 주요 동작 변화: 메모로 이동할 때 입력·조합 중 글자를 먼저 확정하거나 이동을 거절합니다. 입력칸(자간·문단 간격 등)에서는 문서 단축키(Ctrl+Z/Y/B/I/U/A)가 입력칸의 것으로 동작하고 Ctrl+S는 그대로 저장합니다. 조합 중 좌우 방향키는 문단 이동을 하지 않습니다. 구역 끝에서 앞으로 지우기는 다음 구역과 합치지 않습니다. 두 손가락 확대의 최소 배율은 Ctrl+휠과 같은 50%입니다. 모든 파일 접근을 회수하면 공유 저장공간의 낡은 목록을 지우고 연결 폴더만 다시 찾습니다. 시스템 글자 크기를 키워도 편집 입력칸 글자는 페이지 글자와 같은 크기를 유지하도록 WebView 글자 배율을 측정해 보정합니다. Termux 검색은 연결 폴더를 먼저 찾고 별도 스레드에서 실행하며 순환 링크·`node_modules`·점 폴더를 건너뜁니다. 순환 링크는 제공자가 같은 폴더를 알려 주는 방법이 없어 목록으로만 알아볼 수 있으므로, 조상과 같은 목록을 가진 폴더는 아래 폴더들도 3단계 같게 이어질 때만 별칭으로 보고 건너뛰며(그 폴더는 '건너뜀'으로 세어 검색을 '완료'로 보지 않고, 목록에서 사라진 문서의 참조도 지우지 않습니다), 확인 범위 안에서 차이가 나타나는 진짜 중첩 폴더는 계속 검색합니다. 확인 범위까지 같은 구조가 이어지면 별칭과 구별할 수 없어 해당 폴더를 건너뛰고 불완전 검색으로 표시합니다. 폴더 하나가 자기 몫(문서 한도의 공평한 몫)에 닿아도 다음 폴더 검색은 계속하고, 취소나 전체 시간 한도(150초)에서만 멈춥니다. 별칭 확인 조회도 같은 시간 한도·항목 한도 안에서만 하며(조회 시간은 남은 시간으로 제한, 목록이 2,000개 이상이면 비교할 수 없어 '건너뜀', 읽은 항목은 폴더 항목 한도에 합산, 확인 조회 240회는 연결 폴더마다 몫으로 나눔, 확인 응답 없음이 누적 3번 생기면 확인 중단). 폴더 선택 화면이 열린 동안 앱이 종료돼도 선택한 폴더를 연결합니다. 설치 APK 시험은 응답 없음(ANR)·충돌 대화상자를 시나리오마다 검사해 앱이나 알 수 없는 ANR을 실패로 처리합니다.
