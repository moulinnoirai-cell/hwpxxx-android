# DeX 사용자 관점 시험

대상은 외부 모니터에서 물리 키보드·마우스를 사용하는 편집 흐름입니다. 본문 클릭은 배율을 바꾸지 않습니다.

## 조작

- Ctrl+마우스 휠: 포인터 위치를 기준으로 문서만 확대/축소(50~400%). 일반 휠: 문서 스크롤.
- Ctrl+0: 문서 맞춤 배율. Ctrl++ / Ctrl+-: 문서 확대/축소. 편집 패널의 배율 단추도 같은 동작입니다.
- Ctrl+S / Ctrl+Shift+S: 저장 / 다른 이름으로 저장.
- Ctrl+B/I/U, Ctrl+Z/Y, Ctrl+Shift+Z: 글자 서식과 실행 취소/다시 실행.
- Alt+C: 모양 복사/적용. Ctrl+Home/End: 문서 처음/끝. PageUp/Down: 문서 스크롤. Ctrl+↑/↓ 및 문단 경계의 ←/→: 이전/다음 문단 이동. 문단 끝 Delete: 다음 문단 잇기.
- 메모 대화상자 Ctrl+Enter: 메모 저장. Esc: 대화상자 닫기 또는 도구 모드 해제.
- 글자 선택·복사·잘라내기·붙여넣기는 입력칸의 표준 키보드/마우스 동작을 사용합니다. 현재 편집 범위는 선택한 한 문단입니다. 여러 문단을 붙여 넣는 동작과 표 안 붙여넣기는 지원하지만, 마우스로 여러 문단을 한 번에 선택하는 PC판 전체 선택 모델은 이식하지 않았습니다.

## 검증 계층

1. WASM Worker 시험: Unicode·여러 문단 붙여넣기, 메모 겹침 거부, 잘못된 서식, 과도한 요청, stale selection, 저장 bytes 검증, 되돌리기 분기, 문서 탐색.
2. Chromium 시험: 네 가지 창 크기에서 실제 휠/키 이벤트, 배율과 입력 요소 유지, 형광펜과 메모, 회전·창 크기 변경.
3. 설치 APK 시험: Android API 30, 33(탭 S7 최종 Android 세대), 35. 실제 WebView/OfflineNative/공유 저장공간과 Android 설정을 사용합니다. 저장·재열기·백업·충돌·암호 문서·손상 파일·PDF·이동·권한 회수·백그라운드·프로세스 종료를 확인합니다. 브리지를 가짜로 바꾸지 않습니다.

각 에뮬레이터의 `.qa/android-<API>/results.json`, 시나리오별 PNG, logcat을 Actions artifact에 보관합니다. 통과 여부는 해당 커밋의 실행 결과를 기준으로 판단합니다.

## 범위의 한계

AOSP 에뮬레이터는 Samsung DeX 펌웨어·Samsung IME·Bluetooth 무선 연결을 구현하지 않습니다. 해당 세 가지는 실제 기기 확인이 필요합니다. 강제 종료 전 저장하지 않은 편집 내용은 메모리에만 있으므로 복구되지 않습니다. 이 경우 원본 파일과 저장 완료 파일이 유지되는지를 검증합니다. 저장공간 부족·메모리 부족의 모든 시점을 재현했다는 의미도 아닙니다.
