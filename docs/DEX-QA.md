# DeX 사용자 관점 시험

대상은 외부 모니터에서 물리 키보드·마우스를 사용하는 편집 흐름입니다. 본문 클릭은 배율을 바꾸지 않습니다.

## 조작

- Ctrl+마우스 휠: 포인터 위치를 기준으로 문서만 확대/축소(50~400%). 일반 휠: 문서 스크롤.
- Ctrl+0: 문서 맞춤 배율. Ctrl++ / Ctrl+-: 문서 확대/축소. 편집 패널의 배율 단추도 같은 동작입니다.
- Ctrl+S / Ctrl+Shift+S: 저장 / 다른 이름으로 저장.
- Ctrl+B/I/U, Ctrl+Z/Y, Ctrl+Shift+Z: 글자 서식과 실행 취소/다시 실행.
- Alt+C: 모양 복사/적용. Ctrl+Home/End: 문서 처음/끝. PageUp/Down: 문서 스크롤. Ctrl+↑/↓ 및 문단 경계의 ←/→: 이전/다음 문단 이동. 문단 끝 Delete: 다음 문단 잇기.
- 메모 대화상자 Ctrl+Enter: 메모 저장. Esc: 대화상자 닫기 또는 도구 모드 해제.
- 글자 선택·복사·잘라내기·붙여넣기는 입력칸의 표준 키보드/마우스 동작을 사용합니다. 한 문단 안의 선택은 브라우저 선택, 문단을 넘는 마우스 드래그·Shift+클릭·Ctrl+A(두 번째)는 엔진 선택 범위입니다. 범위에서는 Ctrl+C/X, Backspace/Delete, 입력, Enter, 붙여넣기, Ctrl+B/I/U, 형광펜, Ctrl+Z/Y가 한 번에 동작하고 화살표·Esc는 선택을 해제합니다. 표 경계·구역 경계를 넘는 선택과 범위 안의 메모 달기·모양 복사는 지원하지 않습니다.
- Ctrl+A는 첫 번째에 현재 문단 전체, 두 번째에 본문 구역(표 칸 안이면 그 칸) 전체를 선택합니다.

## 검증 계층

Android 엔진은 WebAssembly MVP 대상으로 표준 라이브러리까지 빌드합니다. 빌드 방법과 고정 값은 `patches/rhwp-engine/README.md`와 `config/android-engine.json`에 있고, 포장되는 엔진은 매 Gradle 빌드 전에 `scripts/verify-engine.mjs`(`verifyMemoEngine`, 끌 수 없음)가 검사합니다: 생성된 `build-info.json`이 있어야 하고, 고정 값(본가 커밋·패치 SHA-256·Rust·wasm-bindgen·플래그)을 그대로 담아야 하며, `rhwp.js`·`rhwp_bg.wasm`·`rhwp.d.ts`의 실제 SHA-256이 그 기록과 같아야 합니다(새 glue와 낡은 바이너리 조합 거부). 시험은 `tests/engine-integrity.test.mjs`입니다. Rust 공식 [구형 Wasm 대상 빌드 안내](https://doc.rust-lang.org/stable/rustc/platform-support/wasm32-unknown-unknown.html)에 따라 `-Ctarget-cpu=mvp`와 `-Zbuild-std`를 함께 사용합니다.

1. WASM Worker 시험: Unicode·여러 문단 붙여넣기, 메모 겹침 거부, 잘못된 서식, 과도한 요청, stale selection, 저장 bytes 검증, 되돌리기 분기, 문서 탐색, 여러 문단 범위(선택·복사·삭제·바꾸기·서식·실행 취소·표 보호·메모 동반 삭제, HWP/HWPX), 엔진 클립보드 붙여넣기, 표 칸별 붙여넣기, 복구본 내보내기가 저장 기준선을 바꾸지 않는지, 암호 문서(암호 요구·불일치·유지).
2. Chromium 시험: 네 가지 창 크기에서 실제 휠/키 이벤트, 배율과 입력 요소 유지, 형광펜과 메모, 회전·창 크기 변경(`tests/tablet-ui.py`). `tests/dex-ui.py`는 1920×1080에서 실제 마우스 드래그·Shift+클릭·Ctrl+A, 범위 서식·삭제·입력·실행 취소, 표 칸별 붙여넣기, 편집 중 종료 뒤 복구(복구본 → 새 파일 저장, 원본 해시 불변), 4초 쉬지 않는 40초 연속 입력에서 15초에는 복구본이 없고 약 30초에 생기며 복구본에서 입력의 앞부분이 돌아오는지, 저장이 7초 걸리다 외부 변경으로 실패할 때 저장 중에는 복구본을 쓰지 않고 실패 직후 새 입력 없이 복구본이 생기며 원본 바이트는 그대로이고 복구·삭제가 되는지(`/__delay` 미리보기 지연), 외부 변경 충돌, 암호 문서 PDF 저장을 미리보기 서버(실제 파일 작업)와 함께 확인합니다. `tests/review-ui.py`는 Opus 리뷰 항목(메모 이동이 입력 중·조합 중 글자를 잃지 않는지, 메모 상자 클릭, 입력칸의 Ctrl+Z/B, 조합 중 방향키, 두 손가락 확대와 Ctrl+휠의 최소 배율, 파일 접근 회수 뒤 목록)을 같은 방식으로 확인합니다. 이 미리보기에서 Termux 연결은 시험용 가짜 브리지이며 Termux 동작의 근거가 아닙니다.
3. 설치 APK 시험: 사용자 기기인 갤럭시탭 S7의 Android 13(API 33)을 최종 검증 대상으로 사용합니다. 실제 WebView/OfflineNative/공유 저장공간과 Android 설정을 사용합니다. 저장·재열기·백업·충돌·암호 문서·손상 파일·PDF·이동·권한 회수·백그라운드·프로세스 종료를 확인합니다. 브리지를 가짜로 바꾸지 않습니다. 마우스 범위 선택, 표 칸별 붙여넣기, 암호 문서 PDF, 프로세스 종료 뒤 복구본 복구(복구본이 실제로 쓰일 때까지 기다린 뒤 `am force-stop`)와 쉬지 않는 연속 입력의 최대 대기(30초) 복구본은 `tests/android-emulator.cjs`에 시나리오로 추가했으며(작성만 했고 이 환경에서는 실행하지 못함), 메모 이동이 입력 중·조합 중 글자를 잃지 않는지와 저장된 파일 재열기, 입력칸 단축키, 큰 글자 크기에서 편집 글자 정렬(WebView 글자 배율 보정)도 같은 파일에 있습니다. 이 시나리오의 통과는 해당 커밋의 Actions 실행 결과로만 판단합니다.
4. Termux 통합 시험: 공식 GitHub v0.118.3 x86_64 APK를 설치하고 실제 `com.termux.documents` 제공자와 시스템 폴더 선택 화면을 사용합니다. 앱 내부 HOME의 프로젝트·중첩 폴더 검색, 선택하지 않은 형제 폴더 제외, 선택 취소, 재시작 후 권한 유지, 중복 연결, 삭제된 파일, 복사본 저장, 연결 해제, 심볼릭 링크 순환·`node_modules`·점 폴더·70단계 깊이 함정(문서가 늘지 않고 검색이 한도 없이 끝나는지; 별칭으로 건너뛴 폴더가 있으면 검색을 '완료'로 보지 않음은 JVM 시험 `TermuxWalkerTest`가 확인), 각 시나리오가 정확한 문서 이름 목록(`termux-nested.hwpx` 등)을 기대하는지(`tests/android-termux-fixtures.test.mjs`가 시나리오 순서의 파일 삭제와 기대 목록이 맞는지 정적으로 점검), 폴더 선택 화면이 열린 채 앱 프로세스가 종료돼도 선택한 폴더가 연결되는지를 검증합니다. 테스트용 Termux는 배포 APK에 포함하지 않습니다.

각 에뮬레이터의 `.qa/android-<API>/results.json`, 시나리오별 PNG, logcat을 Actions artifact에 보관합니다. 통과 여부는 해당 커밋의 실행 결과를 기준으로 판단합니다.

설치 APK는 외부 모니터를 가정한 1920×1080 / 160dpi 창에서 시험하고, 작은 창은 700×500으로 확인합니다. 탭 S7 자체의 논리 화면인 1280×800, 같은 비율의 세로 화면, FHD 모니터와 휴대폰 크기는 별도 Chromium 시험으로 확인합니다. CI의 2코어 KVM에서 소프트웨어 렌더링을 사용하며, 삼성 기기 자체를 에뮬레이션하는 것은 아닙니다.

설치 APK의 WebView에는 ADB 포트 포워딩과 CDP로 직접 연결합니다. 시험용 Playwright는 공식 Android 백엔드와 같은 `clank` 모드로 초기화해 WebView에 없는 브라우저 다운로드 관리자 명령을 호출하지 않습니다. 구형 WebView의 가시성 판정도 사각형 기반으로 호환 처리합니다. 이 두 처리는 시험 도구에만 적용하며 앱 브리지·엔진·저장소 응답은 바꾸지 않습니다. 화면을 켜고 잠금을 해제한 에뮬레이터에서 실제 ADB 화면 캡처와 입력도 사용합니다.

에뮬레이터의 System UI/Pixel Launcher 응답 없음(포커스 창 `Application Not Responding: com.android.systemui` 또는 `com.google.android.apps.nexuslauncher`이고 대화상자 글이 같은 프로세스를 가리킬 때만)이 발생하면 실제 시스템 대화상자의 ‘대기’를 선택해 진행할 수 있습니다. 해당 복구는 최대 4회이며 `.qa/android-system-33/`의 `N.xml`·`N.png`·`N.after.png`·`N.focus.txt`·`N.logcat.txt`·`recoveries.json`(원래 포커스·횟수 포함)과 실행 로그에 별도 기록합니다. 로컬 재실행은 이전 기록을 지우고 시작하며, 두 시험 묶음은 한 기록을 공유합니다.

앱 자체나 알 수 없는 응답 없음(Termux·DocumentsUI·Google 서비스 등)과 오류(충돌) 대화상자는 자동으로 닫지 않고 실패합니다. CDP로만 진행되는 시나리오에서는 ANR 창이 화면을 덮어도 단계가 통과하므로, 두 시험 묶음(`android-emulator.cjs`, `android-termux.cjs`) 모두 ① 시나리오가 끝날 때마다, ② 모든 Back 키 전에, ③ 끝날 때(logcat events/main/system의 `am_anr`·`ANR in`, crash 버퍼) 포커스와 로그를 확인하고, ④ 3초마다 백그라운드로 포커스를 살펴 곧바로 사라지는 창도 기록합니다. 실패하면 대화상자를 건드리지 않은 채 `failure-N.{focus.txt,xml,png,logcat.txt}`와 `anr-failures.json`을 남기고 `android-suites.cjs`가 실행 전체를 실패로 처리합니다. Android 오류 대화상자나 ANR 보고 기능을 비활성화하지 않습니다. 판단 규칙과 실제 형식(`dumpsys window`·uiautomator·logcat 표본)은 `tests/android-anr.test.mjs`가 기기 없이 검증합니다.

## Termux 폴더 사용

문서함의 설정 → **Termux 프로젝트 폴더 연결**에서 Termux의 프로젝트 폴더를 선택합니다. 하위 폴더의 HWP/HWPX를 문서 이름으로 검색할 수 있습니다. 폴더 연결은 재시작 후에도 유지되며 8개까지 지원합니다. 연결 해제는 파일을 삭제하지 않습니다.

Termux 내부 폴더에는 전체 파일 접근 권한만으로 접근할 수 없습니다. 사용자가 선택한 폴더의 읽기 권한만 유지합니다. 편집 후 Ctrl+S는 기기 저장소에 복사본을 저장합니다. Termux 원본의 직접 덮어쓰기·이름 변경·이동·삭제는 제공하지 않습니다. 일반 저장공간의 원본 저장은 기존 방식으로 동작합니다. 검색은 연결한 Termux 폴더를 먼저, 그다음 기기 저장공간을 찾으므로(연결 폴더 몫 5,000개) 기기 저장공간이 아주 커도 연결 폴더가 가려지지 않고, 연결 폴더가 여러 개이면 각 폴더가 남은 한도의 몫을 받습니다. 점으로 시작하는 폴더(`.git`·`.cache`…), `node_modules`, `__pycache__`와 Termux 홈의 `storage`(termux-setup-storage가 만드는 공유 저장공간 링크)는 검색하지 않습니다. 같은 폴더가 심볼릭 링크로 다시 나타나는 순환(`loop -> ..`)은 목록이 상위 폴더와 같을 때 한 번 조회한 뒤 건너뜁니다(서로 복사한 형제 폴더는 그대로 모두 찾습니다). 형제 폴더로 향하는 링크는 구별하지 못해 문서가 한 번 더 나올 수 있습니다. 64단계보다 깊은 폴더는 ‘건너뜀’으로 세고 나머지 검색은 계속합니다. 문서 10,000개·폴더 50,000개·항목 150,000개·150초의 한도에 도달하면 안내합니다. 검색은 다른 작업(상태·열기·저장)과 별도 스레드에서 실행되며 제공자 호출마다 제한 시간과 취소가 있습니다.

## 범위의 한계

AOSP 에뮬레이터는 Samsung DeX 펌웨어·Samsung IME·Bluetooth 무선 연결을 구현하지 않습니다. 해당 세 가지는 실제 기기 확인이 필요합니다. 강제 종료 전 저장하지 않은 편집은 비공개 복구본에서 복구합니다(입력을 잠시 쉴 때(보통 약 4초, 큰 문서는 최대 30초), 백그라운드로 갈 때, 쉬지 않고 입력해도 최대 30초 안에 기록). 복구본은 마지막으로 성공한 스냅숏까지만 담으므로 그 뒤의 입력(계속 입력 중이면 최대 약 30초 분량)은 사라질 수 있고 어떤 종료에서도 복구된다는 보장은 아니며, 복구본을 쓰지 못한 경우(저장공간 부족 등)에는 화면에 알립니다. 원본 보존(원본·저장 완료 파일의 해시 불변)과 편집 복구는 서로 다른 검증이며 둘 다 시험합니다. 저장공간 부족·메모리 부족의 모든 시점을 재현했다는 의미도 아닙니다.

## 아직 되지 않은 것과 이유

- 겹친 표(표 안의 표) 칸 합치기: 엔진 0.8.7의 `mergeTableCells`가 본문 수준 컨트롤 번호만 받고 경로(path) 변형이 없습니다. 엔진 수정이 필요합니다.
- 한/글 전용 HTML 클립보드: 같은 형식의 클립보드를 Android에서 만들거나 확인할 수 없어 켜지 않았습니다. 엔진 클립보드(같은 문서 안)와 일반 글자 붙여넣기만 지원합니다.
- 표 경계·구역 경계를 넘는 선택, 표 안의 표 문단 서식: 엔진 API가 한 본문 구역/한 칸 단위이고 중첩 칸 문단 서식 API가 없습니다.
- 실제 한컴 프로그램에서 저장본을 다시 여는 확인, 실제 Tab S7·DeX·삼성 키보드·Bluetooth는 이 환경에서 시험하지 못했습니다.
