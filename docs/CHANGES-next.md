# Android 다음 버전 — 닫은 탭이 "새 문서"로 되살아나지 않게

기준: Android 0.4.1. 엔진·편집기는 그대로 rhwp v0.9.1입니다. 버전 번호는 릴리스할 때 올립니다.

## 고친 점

- 파일 앱에서 문서를 열면 그 문서 옆에 "새 문서" 탭이 1~2개 더 생기던 문제를 고쳤습니다. 원인은 두 가지였습니다.
  - 저장하지 않고 닫은 탭의 복구 자료가 일부 남아, 다음 실행 때 그 탭이 오른쪽 끝에 "새 문서"로 다시 생겼습니다.
  - 앱이 강제 종료된 뒤 다시 켜면, 복구 자료가 없는 탭도 빈 "새 문서"로 되살아났습니다.
- 탭을 닫으면 그 탭의 복구 자료를 모두 지웁니다. 그 탭에 다른 문서의 복구 자료가 남아 있으면 이름과 개수를 보여 주고 한 번 더 확인합니다(취소가 기본). 응답 없는 탭이나 아직 열지 않은 탭을 닫을 때도 같은 규칙을 따르고, 확인창에 함께 지워진다고 표시합니다.
- 다시 실행할 때는 복구 자료가 있는 탭만 되살리고, 열리기 전까지 "복구 문서"로 표시합니다. 복구 자료를 확인하지 못한 경우에는 지금처럼 모든 탭을 그대로 둡니다. 강제 종료에 대비한 복구는 그대로입니다.
- 앱이 켜져 있을 때 파일 앱에서 문서를 열면, 지금 탭이 아니어도 이미 준비된 빈 새 문서 탭이 있으면 그 탭으로 옮겨 엽니다.

## 진단 보강

- 문서를 읽다 실패하면 문구 끝에 단계를 붙입니다: `(단계: 파일 읽기)`, `(단계: 복구 자료 읽기)`, `(단계: 앱 내부 전달)`, 파일 앱에서 받은 파일은 `(단계: 받은 파일 확인)`. 단계가 없는 "파일 로드 실패"는 편집기의 해석(파싱) 단계입니다.
- 앱의 읽기 버퍼가 잠시 차 있거나("다른 문서를 처리 중") 파일 제공자가 늦을 때("제한 시간") 한 번 자동으로 다시 읽습니다.

## 확인한 것

- 2026-11-25 파일 앱에서 열리지 않는다고 보고된 rhwp 생성 hwp·hwpx는 압축 검사, 앱 Java 검증, 엔진 파싱과 쪽 그리기, 설치본 Studio의 "파일 앱에서 받은 문서" 경로에서 모두 정상으로 열렸습니다. 실기기에서만 실패하는 원인은 아직 찾지 못했습니다. 위 단계 표시로 다음 실패 때 원인을 좁힙니다.
