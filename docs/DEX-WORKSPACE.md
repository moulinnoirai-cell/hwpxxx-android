# 여러 문서 탭과 좌우 분할

Android 앱은 데스크톱 Hwpxxx 1.6.1의 실제 Studio 편집기를 문서마다 독립적으로 실행합니다. 한 작업공간에서 최대 5개 문서를 열고, 그중 두 문서를 좌우로 나란히 편집할 수 있습니다.

## 사용법

- 탭은 최상단 메뉴의 **도구 오른쪽 빈 공간**에 표시됩니다. 탭을 위한 별도 행은 만들지 않습니다. 각 분할 화면의 메뉴에서 같은 탭 목록을 사용할 수 있습니다.
- `+` 또는 `Ctrl+T`로 새 문서를 엽니다. 파일 열기와 최근 문서 열기도 새 탭을 사용합니다. 다만 지금 탭이 아무것도 입력하지 않은 빈 새 문서이면 그 탭에서 문서를 엽니다. 파일 앱에서 전달받은 문서도 같고, 지금 탭이 아니어도 이미 준비된 빈 새 문서 탭이 있으면 그 탭으로 옮겨 엽니다. 빈 "새 문서" 탭이 열린 문서 옆에 남지 않습니다.
- 탭을 클릭하거나 `Ctrl+Tab` / `Ctrl+Shift+Tab`으로 문서를 전환합니다. 각 문서의 편집 내용, 커서, 실행 취소 기록과 저장 대상은 그 문서에 남습니다.
- 탭을 마우스로 끌면 삽입 위치 표시가 나타납니다. 원하는 위치에 놓아 순서를 바꿉니다. 순서 변경은 좌우 문서 배치나 문서 내용을 바꾸지 않습니다. 목록이 길면 탭 영역에서 휠로 가로 이동할 수 있습니다.
- **좌우 분할** 버튼으로 두 문서를 나란히 표시합니다. 이미 보이는 문서의 탭을 선택하면 그쪽으로 초점이 이동합니다. 숨겨진 문서를 선택하면 조작한 쪽의 문서를 교체합니다. 분할을 해제해도 다른 탭은 열려 있습니다.
- 탭의 `×` 또는 `Ctrl+W`로 문서를 닫습니다. 수정한 문서는 저장·버리기·취소를 확인합니다. 닫은 탭의 복구 자료는 함께 지웁니다. 그 탭에 다른 문서의 복구 자료가 남아 있으면 이름과 개수를 보여 주고 한 번 더 확인합니다(취소가 기본). 그래서 닫은 탭이 다음 실행 때 "새 문서"로 되살아나지 않습니다. 마지막 탭을 닫으면 앱이 종료됩니다. 입력 조합 중이거나 대화상자가 열려 있으면 탭 단축키가 편집을 가로채지 않습니다.
- 글꼴 등록 목록은 모든 문서에서 공유합니다. 글꼴을 가져와도 다른 문서의 선택 영역이나 서식은 바뀌지 않습니다. 지원 파일과 사용법은 [글꼴 안내](ANDROID-FONTS.md)를 참고하세요.

## 저장과 복구

문서마다 별도 WebView, WASM 편집기, 파일 핸들, 저장 요청, 임시 데이터, 복구 영역을 사용합니다. 탭을 바꾸거나 순서를 바꿀 때 편집기를 다시 로드하지 않습니다. 두 탭에서 같은 파일을 열어 먼저 저장한 뒤 다른 탭에서 오래된 내용을 저장하면 변경 충돌을 알려 원본 덮어쓰기를 거절합니다. 다른 이름으로 복사본을 저장할 수 있습니다.

편집기가 준비되지 않거나 응답하지 않아 일반 닫기 확인을 실행할 수 없으면 Android 확인창을 표시합니다. 취소가 기본 선택이며, 사용자가 닫기를 선택하면 저장하지 않은 변경사항과 그 탭의 복구 자료가 함께 지워진다고 알립니다. 아직 열지 않은 탭을 닫을 때도 남은 복구 자료의 이름과 개수를 알리고, 확인하면 함께 지웁니다. 정상 확인창이 열려 있으면 그 결정을 기다립니다.

닫기 확인이 2분을 넘으면 요청이 만료되어 탭이 남을 수 있습니다. 파일 선택·저장 대화상자를 마친 다음 닫기를 다시 시도하세요. 저장한 파일을 되돌리거나 지우지는 않습니다.

탭 ID·순서·좌우 배치는 비공개 작업공간 파일에 저장합니다. 이 파일에는 문서 이름·경로·본문·암호를 기록하지 않습니다. 프로세스가 종료되면 메모리의 실행 취소 기록까지 복원되지는 않습니다. 다시 시작할 때는 복구 자료가 있는 탭만 되살리고, 열리기 전까지 "복구 문서"로 표시합니다. 복구 자료가 없는 탭은 빈 "새 문서"로만 돌아오므로 되살리지 않습니다(남는 탭이 없으면 빈 탭 하나). 복구 자료를 확인하지 못한 경우에는 모든 탭을 그대로 둡니다. 원본 파일을 자동으로 다시 여는 세션 복원은 하지 않습니다.

복구는 탭별 비공개 영역에 보관합니다. 탭당 기존 8개 기록 / 128 MiB 제한과 전체 512 MiB의 복구 기록 수용 한도가 적용됩니다. 기존 초과 자료는 보존하고, 교체 중에는 임시 파일 최대 32 MiB와 메타데이터 공간을 추가로 사용할 수 있습니다. 전체 한도가 찼을 때 다른 탭의 복구를 지우지 않고 복구 자료 저장 실패를 알립니다. 원본 문서 저장은 계속 사용할 수 있습니다. 기존 버전의 복구 자료는 소유 탭을 먼저 영구 기록한 다음 복사·검증하며, 충돌하거나 읽을 수 없는 자료는 보존합니다. 한 번에 표시할 수 없는 복구 탭도 디스크에서 삭제하지 않습니다.

5개 제한은 독립 편집기의 메모리 사용을 제한하기 위한 것입니다. 재시작할 때 숨겨진 탭은 처음 선택할 때 편집기를 준비합니다. 한 번 연 편집기는 탭 전환 후에도 유지하므로 큰 문서를 많이 열면 기기 메모리에 영향을 줄 수 있습니다.

## 구현과 검증 경계

`WorkspaceModel`은 탭·활성 문서·좌우 배치를 관리하고, `WorkspaceStateStore`는 불투명 ID와 배치만 저장합니다. `WorkspaceRequests`는 파일 선택 결과와 닫기 응답을 요청한 탭의 실행 인스턴스에 묶습니다. `WorkspaceServices`는 글꼴·최근 기록·파일 저장소와 복구 용량 관리를 공유합니다. `MainActivity.EditorSession`은 개별 편집기와 콜백의 소유자입니다.

`studio-host.js`가 `/workspace-tabs.mjs`를 연결합니다. 네이티브 `workspaceEnabled()`로 기능을 확인한 뒤 `workspaceReady`의 스냅샷을 표시합니다. 스냅샷은 `selfId`, 탭 목록, `activeId`, `primaryId`, `secondaryId`, `split`, `maxTabs`를 포함합니다. 새 문서·선택·닫기·분할·순서 변경은 네이티브 작업공간으로 요청하고, 네이티브가 각 편집기에 갱신을 전달합니다. JS가 전달한 원본 탭 ID를 콜백 권한으로 신뢰하지 않습니다. 탭 드래그는 전용 MIME만 사용합니다.

Studio 패치 `0115`는 새 문서·파일·최근 문서 열기를 새 탭으로 연결합니다. 새 탭의 초기 열기는 명령별 표시로 한 번만 실행하여 다시 새 탭을 만드는 재귀를 막습니다. 이전 단일 문서 호스트는 기능 확인 결과가 없으면 기존 동작을 사용합니다. 기능을 지원하는 호스트에서 준비 요청이 실패하면 오류를 알리고 현재 문서 교체를 차단합니다.

JVM 검사는 모델·영속 상태·동시 저장·복구 용량·요청 소유권을 확인합니다. Chromium 검사는 실제 배포용 Studio/WASM과 탭 UI를 실행하지만, Android 브리지는 테스트 대역입니다. 이 검사는 Android의 실제 두 WebView 부착, 시스템 파일 선택 결과 재전달, 공유 렌더러 종료, DeX 창 관리와 물리 키보드·마우스의 기기 동작을 증명하지 않습니다. Samsung DeX 실기기 확인은 별도로 필요합니다.

주요 회귀 검사:

```bash
STUDIO_WORKSPACE_SRC="$PWD/.build/studio-src" node --test tests/studio-workspace-host.test.mjs tests/workspace-oracle.test.mjs tests/workspace-server.test.mjs
python tests/studio-workspace.py --root-announced-build --workspace
```

위 명령은 먼저 엔진과 패치를 적용한 Studio 빌드를 준비하고 Playwright·Chromium을 설치한 환경에서 실행합니다. 전체 빌드·JVM 검사 명령은 `.github/workflows/android.yml`에 있습니다.
